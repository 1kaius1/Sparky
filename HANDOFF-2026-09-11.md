## The two features bundled in this snapshot

### 1. SSE-refresh scoping fix

Fixes a real bug: opening a dropdown on, e.g., the Profiles page would close
itself almost immediately, because any SSE progress/instance event triggered
an unconditional full `#main-content` refetch regardless of which page was
open. Full assessment, root cause, and the 5 decisions made to fix it are
written up in `FIX_REFRESH.md` (already committed as part of this diff) -
read that file for the real detail. Short version: `web/static/js/sse.js`
gained a `data-sse-topics` per-page opt-in (a page only auto-refreshes for
topics it declares) plus a focus guard (don't refresh out from under a form
control someone's actively using), and 5 page templates got the
`data-sse-topics="..."` wrapper.

### 2. Dashboard enhancement (built on top of #1)

Replaces the old "Recent running instances" 3-column table with a real
operational view: per-instance model/engine/node/started/uptime/status, plus
two rolling inline-SVG load-strip columns (GPU util %, GPU mem %) sourced
from a new `GET /dashboard/live-data` endpoint, polling in place (no full
page refetch) the same way the Metrics page already does. Design decisions
(why two columns not one, why hand-rolled SVG not Chart.js, the ~24-bar/~2min
window, the known one-instance-per-node GPU-attribution limitation) are in
`PLANNING.md`'s 2026-09-10 Decisions Log entry and Known Issues row - read
those for the real detail.

**Both features are fully built and were validated working** (real dev
server, both Sparks registered and running real models, SSE-scope
confirmed fixed, dashboard load strips confirmed live-updating) before this
handoff - this is not half-finished work, it's finished work that just never
got committed because of an explicit "don't commit until I review" hold.
