General


? This name is the model id clients use: it is what API clients and editor extensions list and must send as model, and it must be unique. Use letters, digits and . _ - : only, at most 64 characters, starting with a letter or digit - no spaces or commas. A / is allowed between parts (team/qwen3:7b), but some clients treat / and : specially, so prefer plain names. Make it self-describing, because several profiles can load the same model with different engines or parameters and every one needs a name that tells it apart. A good shape is <model>-<quantization>-<engine>-<what differs>, for example Qwen3-Coder-Next-NVFP4-GB10-vllm-tp2-ctx32k. Avoid names starting with o and a digit, or containing gpt-5, claude, codex, grok-4 or deepseek-r: some clients change how they send requests when an id looks like those.




Only models already present on the target node's own Inventory are offered - see the Inventory page to download or copy one there first.


Engine





Any engine flag without its own key goes in extra_args, a list of command-line arguments added after the others exactly as written, for example {"extra_args": ["--enable-prefix-caching", "--attention-backend", "flashinfer"]}. The model, port, host and served model name are set by Sparky and cannot be given there.

Environment variables



One NAME=value per line, passed to the engine process on every kind of node. Values are taken literally (no quotes or ${} expansion). They are stored as written and shown here in plain text, so avoid putting a credential in one for now. On a Docker or Podman node a name set here replaces one of the same name that Sparky sets for GPU access.

Container (Docker and Podman nodes only)

These are the equivalents of docker run / podman run flags. Leave a field blank to keep the runtime's default. They are refused for a node that runs engines as a plain process (bare-metal).



Overrides the engine type's default container image. Leave blank to use the default image for this engine type.



Multi-GPU tensor-parallel launches need far more than the default for the engines to talk to each other.



With host the container uses the node's own shared memory, so a shared memory size above has no effect on Podman.



With host the engine listens on the node's own port directly and Sparky publishes no port.




A replacement entrypoint runs exactly as written followed by the engine's arguments, so Sparky stops adding vllm serve itself. Clearing it leaves Sparky adding vllm serve to the arguments.
